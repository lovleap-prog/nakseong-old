# 초등 과학 인터랙티브 수업 만들기

이 저장소는 초등 과학 단원을 «표지 → 체험 장 여러 개 → 확인» 슬라이드로 만든다. 계절의 변화(`src/season`)와 전기의 이용(`src/electric`)이 완성된 본보기다. 새 단원은 이 둘과 같은 틀, 같은 품질로 만든다.

결과물을 쓰는 사람은 교실의 선생님과 초등학생이다. 선생님은 교과서와 한 글자라도 어긋나면 수업에 쓰지 못하고, 학생은 글이 많거나 조작이 어려우면 따라오지 못한다. 그래서 이 일의 품질은 코드 솜씨보다 **교과서를 정확히 읽는 것**과 **직접 띄워서 확인하는 것**에서 갈린다. 아래 순서를 건너뛰지 않는다.

## 순서

1. 교과서 읽기 → 2. 수업 설계 → 3. 뼈대 만들기 → 4. 장 채우기 → 5. 점검하고 고치기 → 6. 저장·게시 → 7. 보고

### 1. 교과서 읽기

사용자가 단원마다 «과학»과 «실험 관찰» PDF를 준다. 주지 않았다면 받기 전에는 만들지 않는다. 기억에 의존해 단원을 지어내면 출판사마다 다른 차시·용어·쪽수가 틀린다. PDF가 없다고 하면 교육과정 수준으로만 만들 수 있다는 점과 틀릴 수 있는 곳을 먼저 말한다.

```bash
pdftotext -layout 과학.pdf - 2>/dev/null | sed 's/[ \t]\+/ /g' | grep -v '^ *$'
```

글자 추출은 순서가 뒤섞이고 그림 속 정보가 빠진다. 그림을 보고 판단해야 하는 것(회로가 어떻게 연결됐는지, 지구본이 어느 쪽으로 기울었는지, 그래프 눈금)은 쪽을 그림으로 뽑아 직접 본다. 작게 보이면 그 부분만 잘라 크게 뽑는다.

```bash
pdftoppm -r 70 -f 5 -l 5 -png 과학.pdf out/p            # 5쪽 전체
pdftoppm -r 170 -f 1 -l 1 -x 320 -y 500 -W 950 -H 640 -png 실험관찰.pdf out/crop   # 일부만 크게
```

PDF 쪽 번호와 교과서 쪽 번호는 다르다(첫 장에 찍힌 쪽수로 차이를 구한다).

읽으면서 아래를 적어 둔다. 이것이 설계의 재료다.

- 단원 도입의 «이 단원을 배우면» 목표와 쪽 범위
- 차시마다: 제목(질문 꼴), 탐구 활동 이름, 준비물, 실험 차례, 측정 조건(시각, 길이, 개수, 전압 같은 숫자), 교과서 쪽과 실험 관찰 쪽
- 차시마다 «정리» 문장. 그대로 «알게 된 것»이 된다
- 실험 관찰에서 학생이 실제로 적는 것(표의 칸, 고르는 보기, 그래프 축). 화면의 표와 물음을 여기에 맞춘다
- 교과서가 쓰는 낱말과 **쓰지 않는 낱말**. 예: 6학년 전기 단원은 «전기가 흐른다»라고 하고 «전류», «전압»을 쓰지 않는다. 쓰지 않는 낱말은 `lesson.json`의 `avoid`에 넣으면 점검이 잡아 준다
- «생각이 쑥쑥» 같은 확장 물음, 안전 주의

### 2. 수업 설계

코드를 쓰기 전에 장 목록을 정한다. 한 장은 교과서 탐구 활동 하나에 대응한다. 만들기·조사·발표처럼 화면으로 옮길 것이 없는 차시는 넣지 않고, 보고할 때 빠졌다고 말한다.

장마다 정할 것:

| 정할 것 | 기준 |
|---|---|
| 2D인가 3D인가 | 아래 «2D와 3D 고르기» |
| 학생이 바꾸는 것 | 실제 실험에서 손으로 바꾸는 것과 같게(시각, 각도, 전지 개수, 스위치) |
| 보이는 결과 | 화면의 변화 + 읽을값 + (값이 여럿이면) 그래프나 표 |
| 해 볼 일 2~4개 | 조작으로 자동 확인되는 것만. 마지막은 보통 «아래 물음에 답해요» |
| 물음 | 방금 본 것에서 답을 찾을 수 있는 것. 실험 관찰의 고르기 문항을 가져온다 |
| 알게 된 것 | 교과서 정리 문장(해요체로만 바꾼다) |
| 선생님 메모 | 발문 1~2개, 실제 실험과 이어 쓰는 법, 지도 유의점 |

표지의 «내 생각 고르기»는 그 단원에서 학생이 흔히 갖는 오개념을 보기로 넣는다(계절: «여름에 태양에 가까워져서»). 마지막 장이 고른 생각을 다시 보여 주며 어느 체험에서 무엇을 봤는지로 바로잡는다.

상호작용의 꼴은 `references/patterns.md`에 본보기와 함께 모아 두었다. 설계할 때 읽는다.

### 2D와 3D 고르기

3D는 만들기도 보기도 비용이 크다. **보는 방향을 바꿔야 이해되는 내용**에만 쓴다. 판단이 서지 않으면 2D로 한다.

- 3D가 맞는 것: 천체의 운동(자전·공전, 낮과 밤, 달의 모양), 태양 고도와 그림자, 땅속·몸속 구조처럼 겉에서 안 보이는 것, 옆에서 본 모습과 위에서 본 모습을 모두 봐야 하는 실험(전자석: 매달린 철 고리는 옆에서, 나침반 바늘은 위에서)
- 2D가 맞는 것: 무엇이 무엇에 연결됐는지가 핵심인 것(전기 회로), 분류·순서·견주기, 양의 크기 비교, 놀이, 그래프
- 하지 않는 것: 교육과정을 넘는 그림. 초등은 입자·분자 모형을 다루지 않으므로 물의 상태 변화나 용해를 분자 그림으로 보여 주지 않는다

사용자에게 장마다 어느 쪽으로 했고 왜 그런지 한 줄씩 알린다.

### 3. 뼈대 만들기

```bash
node .claude/skills/science-lesson/scripts/new-lesson.mjs <id> "<단원 이름>" "<학년 학기 과목 단원>" "<한 줄 요약>"
```

`src/<id>/`에 `lesson.json`, `body.html`, `app.js`, `style.css`가 생긴다. 본보기에는 표지, 2D 장, 3D 장, 확인 장이 하나씩 들어 있고 `TODO`로 채울 곳이 표시되어 있다. `node_modules`가 없으면 `npm install`을 먼저 한다.

### 4. 장 채우기

`body.html`에 글과 틀을, `app.js`에 조작을 쓴다. 공통 도구(`window.Lesson`)의 쓰는 법은 `references/api.md`에 있다. 처음 쓰는 도구는 거기서 서명을 확인하고, 더 긴 본보기가 필요하면 `src/season/app.js`와 `src/electric/app.js`에서 비슷한 장을 찾아 읽는다.

지킬 것과 까닭:

- **계산은 모형에서 나온다.** 값을 손으로 적어 넣지 않고 식으로 구한다(태양 고도는 위도·적위·시각에서, 그림자 길이는 고도에서). 그리고 교과서에 나온 값과 맞는지 한두 점을 견준다(서울의 남중 고도 52°·76°·29°). 식이 맞으면 막대를 어디에 두어도 맞다.
- **교과서 값이 아니면 그렇다고 적는다.** 계산값, 예시값, 단순화한 것은 장 아래 `.fine`에 밝힌다(«기온은 이해를 돕기 위한 예», «크기와 거리는 실제와 다르게 나타냄»). 선생님이 교과서 숫자와 다르다고 물을 때 답이 된다.
- **실험 조건을 교과서와 맞춘다.** 측정 시각, 막대 길이, 전지와 전구의 전압, 카드 이름(가·나·다·라)을 그대로 쓴다. 학생이 실험 관찰에 적은 것과 화면이 나란히 놓인다.
- **직접 재는 활동이면 측정값을 넣을 수 있게 한다.** 화면은 실험을 대신하지 않는다. 실험 관찰이 표를 채우게 하는 활동은 예시값 보기와 «우리 반 측정값» 입력을 함께 둔다(`src/season`의 `day` 장).
- **읽을값은 화면 없이도 바뀐다.** WebGL이 안 되는 기기에서는 `makeView`가 `null`을 돌려준다. 읽을값·표·해 볼 일은 3D와 상관없이 동작하게 쓴다.
- **색은 토큰으로만.** `tok('sun')`, `var(--ink)`. 색 이름과 값은 `src/common/style.css` 맨 위에 있다. 캔버스와 Three.js에도 `tok()`으로 넣는다.
- **글은 짧게, 해요체로.** 학생에게 보이는 글은 해요체(«끌어 보세요», «짧아져요»), 선생님 메모는 합니다체. 한 장의 오른쪽 칸은 읽을값, 해 볼 일, 물음, 알게 된 것이면 충분하다. 조사는 `josa()`로 붙인다(«깡통이», «못이»).
- **교과서 그림과 사진은 가져오지 않는다.** 저작물이다. 도형으로 다시 그린다.
- **움직임은 장이 보일 때만.** `flat`과 `makeView`가 알아서 멈춘다. 계속 도는 움직임은 `reduce`(움직임 줄이기)이면 멈춘다. 소리는 기본으로 끄고 체크했을 때만 낸다(교실에 기기가 서른 대다).
- **Three.js는 r128이다.** `CapsuleGeometry`, `colorSpace` 같은 뒤 판의 기능은 없다. 빛의 세기는 합쳐서 1을 넘기지 않는다(넘으면 바닥이 하얗게 날아간다). 물체가 작게 보이면 카메라를 당기기보다 물체를 키운다.

### 5. 점검하고 고치기

```bash
node .claude/skills/science-lesson/scripts/check.js <id>
```

묶고, 구조·낱말을 점검하고, 장마다 막대를 끝까지 움직이고 단추를 모두 눌러 오류와 가로 넘침을 찾고, 화면을 찍는다. «고칠 것»이 0개가 될 때까지 고친다.

그다음이 더 중요하다. **찍힌 화면을 하나씩 직접 연다**(`.check/<id>/d-*-a.png`, `d-*-b.png`, `m-*.png`). 스크립트는 모양을 판단하지 못한다. 처음 만든 화면에는 거의 항상 이런 문제가 있었다.

- 핵심 물체가 너무 작다(측정기 막대가 점처럼 보임)
- 색이 날아가거나(빛이 셈) 배경과 구분되지 않는다
- 딱지나 물체가 화면 밖으로 잘린다
- 단추와 값이 어색하게 줄바꿈된다
- 3D 화면이 비어 있다

화면을 보고 고친 뒤 다시 찍어 본다. 그리고 점검 스크립트가 하지 못하는 것을 따로 확인한다: **해 볼 일을 차례대로 실제로 해서 «알게 된 것»이 열리는지**. Playwright로 그 장의 정답 경로를 따라 누르고 `.learn.open`이 생기는지 본다(쓰는 법은 `references/api.md`의 «끝까지 해 보기»). 열리지 않는 장은 학생이 영원히 끝내지 못한다.

공통 파일(`src/common/`)을 고쳤다면 다른 단원도 `check.js`로 다시 본다.

### 6. 저장·게시

```bash
node build.mjs <임시 폴더>
```

- `<id>/index.html`: 파일 하나로 열리는 완성본. 저장소에 함께 올린다
- `docs/`: 웹에 올리는 판. 첫 화면에 새 단원이 자동으로 들어간다
- `<임시 폴더>/<id>.html`: claude.ai 게시용 조각

지정된 작업 가지에 올린다. 게시 절차(Artifact 게시와 공유 저장소 선언, GitHub Pages, 수업방)는 `references/publish.md`에 있다.

### 7. 보고

사용자는 개발자가 아닌 선생님이다. 짧고 쉬운 말로 다음을 알린다.

- 링크와, 장마다 교과서 몇 쪽의 무엇을 어떻게 조작하게 했는지(표)
- 장마다 2D·3D 중 무엇을 골랐고 왜인지
- **교과서 값이 아닌 것**: 계산값, 예시값, 교과서에 없는데 더한 조작
- **확신하지 못하는 읽기**: 그림을 보고 판단한 것은 실물과 대조해 달라고 한다(«카드 연결은 사진을 확대해 읽었습니다»)
- 넣지 않은 차시
- 확인한 것과 **확인하지 못한 것**(실제 태블릿 터치, 소리, 고친 뒤 다시 보지 못한 화면)

다 됐다고만 하지 않는다. 선생님은 무엇을 믿어도 되고 무엇을 수업 전에 직접 봐야 하는지 알아야 한다.

## 자주 틀리는 곳

- 교과서를 읽지 않고 아는 내용으로 단원을 짠다 → 차시 구성, 용어, 쪽수가 어긋난다
- 글자 추출만 보고 그림의 내용을 짐작한다 → 회로 연결, 기운 방향이 틀린다
- 교과서에 없는 개념이나 낱말을 넣는다 → `avoid`에 적고 점검한다
- 모든 장을 3D로 만든다 → 연결·분류·비교는 2D가 더 잘 보인다
- 점검 스크립트가 통과했다고 화면을 열어 보지 않는다
- 해 볼 일의 조건이 실제로는 채워지지 않는다(막대의 끝값이 범위 밖, 단추 이름이 다름)
- 머리띠·넘기기 띠의 id를 바꾼다 → 장 넘기기와 따라 넘기기가 멈춘다. 본보기의 `header`와 `footer`는 그대로 둔다
- `data-name`을 한글이나 `settings`·`sidebar` 같은 예약어로 짓는다 → 주소 뒤 `#이름`으로 쓰이므로 영문 소문자로, 뜻이 드러나게 짓는다
- 값을 브라우저 저장소에만 두고 다른 기기에서도 보일 것처럼 말한다 → 기기마다 따로다

## 파일

- `scripts/new-lesson.mjs`: 새 단원 뼈대
- `scripts/check.js`: 묶기 + 점검 + 화면 찍기
- `assets/template/`: 뼈대의 본보기(표지, 2D 장, 3D 장, 확인 장)
- `references/api.md`: 공통 도구와 HTML 틀의 쓰는 법, 끝까지 해 보기
- `references/patterns.md`: 상호작용의 꼴과 본보기, 주제별 2D·3D 판단
- `references/publish.md`: 게시와 수업방
